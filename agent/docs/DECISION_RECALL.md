# Decision 漏抽定位与开发对比

本次修复针对**合并粒度和投票造成的 Decision 丢失**。原来的 Action、Issue 抽取、合并、投票和补回结果保留；
Decision 单独增加三次合并采样，并使用候选编号追踪投票。数量上限仍是 Action 5、Decision 7、Issue 4。

## 对比口径

- 开发会议：TS3006a、TS3006b、ES2011a、IS1008a；没有接触 ES2004、TS3007 留出集。
- 每场前后使用**完全相同的抽取候选**、转写、gold、模型、reasoning effort、数量上限。
- TS3006a/b 的旧候选和合并样本来自已冻结的真实开发基线；另外两场使用本次真实 API 运行保存的样本。
- 对齐沿用 `mta.evaluate.make_llm_matcher`：相同类型、一对一语义匹配、同一模型三次投票，统计 micro P/R/F1。
  最终重放逐类型核对文本列表完全一致后复用这些投票；没有重新抽样评分来挑选较好的结果。
- 这些会议没有提示词示例条目，不需 few-shot 排除。ES2011a 的 Decision、Issue gold 为 `NA.`，
  整个“会议 × 类型”在前后两边同时排除，不把占位条目当真实漏抽，也不把未标注项目当负例。
- 因而 Decision 指标覆盖 3 场、14 条 gold；Action 覆盖 4 场；Issue 覆盖 3 场。
  **不能直接与组员 16 场会议的 0.45 F1 比较。**

这是抽取／合并层的开发对比，包含缓存重放，不是新的真实 Agent 全流程或最终 evaluation。
匹配与候选覆盖归因均由模型投票得到，尚未独立人工复核；宽泛描述是否真正匹配仍需最终评估者检查。

## 决策在哪一步丢失

代码保存的链路为：候选编号 → 每次合并的源成员 → 每次截断 → 投票簇 → 最终截断 → normalize → 最终条目。
`evaluation.json` 为每条 gold 保存候选见证、各样本合并结果、截断后结果、投票后结果与归因。
源成员关系可直接检查；“是否对应同一 gold”的语义判断仍是自动诊断，不等同人工确认。

| 修改前未匹配的决策 | 定位 | 证据 |
| --- | --- | --- |
| TS3006a 营收目标、生产成本 | 合并粒度过粗 | 候选 4/5/6 分别记录售价、营收和成本；两个样本将三者压成一条。它们并非未抽取，合并后一对一评分最多命中一条。 |
| TS3006b LCD／语音识别 | 多数投票 | 候选 5/9 已抽到；有的样本将其与年龄定位合并。旧算法一个宽泛组只能归入一个投票簇，具体功能条目只有 1 票，被过滤。 |
| TS3006b 仅控制电视 | 合并选择 | 候选 12 存在，但没有被三次合并保留下来。 |
| TS3006b 按钮 LED | 多数投票 | 候选 41 存在，合并与投票后未保留。 |
| IS1008a 两条计划／功能设计决策 | 初始候选／类型或表述 | 三票候选覆盖检查未找到匹配见证，需要继续检查初始抽取和分类，不能靠放宽投票补出。 |

这 7 条修改前漏项的自动归因为：初始候选／类型 2、合并选择 1、合并粒度 2、投票 2。
已检查样本中没有发现正确 Decision 因数量截断成为主要漏项，因此本次没有提高数量上限。

## 最终改动

1. 通用合并保留旧提示词和旧投票规则，继续提供 Action、Issue。
2. `decision_consolidate` 用相同候选再采样三次。新的 Decision 合并说明要求区分独立选择，
   不因共享组件、话题、发言者或段落就合并；仍保留原有排除规则和数量上限。
3. 合并项保留 `candidate_indexes`。Decision 投票优先采用观察到的较细分组，
   宽泛组可以为其包含的多个具体选择分别提供一票；同一样本不能为一个选择重复投票。
   这里的票表示源候选被保留，不是又一次独立的事实／证据验证。
4. 新一轮输出只替换 Decision，其他类型结果直接保留。未被更细组完整覆盖的宽泛组不会被静默删除。
5. `decision_consolidate` 逐事件转发 trace，失败时也能保留已完成样本；请求、重试和并发仍共享
   第三步的 80 次调用、100 万 token、请求／整场超时，没有额外的免费额度。

`MTA_DECISION_RECONSOLIDATE=0` 可关闭新增阶段做旧策略消融；默认开启。
`.run.json` 会记录开关、两个提示词的内容／哈希、代码和配置；最终输出 schema 不增加内部候选编号。

## 修改前后结果

最终生产策略的固定样本对比：

| 类型 | TP / 系统条数 / gold：前 → 后 | Precision | Recall | F1 |
| --- | --- | --- | --- | --- |
| Action | 12/19/15 → 12/19/15 | 0.632 → 0.632 | 0.800 → 0.800 | **0.706 → 0.706** |
| Decision | 7/9/14 → 9/13/14 | 0.778 → 0.692 | **0.500 → 0.643** | **0.609 → 0.667** |
| Issue | 2/4/4 → 2/4/4 | 0.500 → 0.500 | 0.500 → 0.500 | **0.500 → 0.500** |

Decision 增加 2 个净匹配，同时多出误报，**precision 有下降**。这是召回与精度的取舍，不是全面提升。

| Decision 分会议 | TP / 系统条数 / gold：前 → 后 | F1：前 → 后 |
| --- | --- | --- |
| TS3006a | 2/3/4 → 4/7/4 | 0.571 → 0.727 |
| TS3006b | 5/5/8 → 5/5/8 | 0.769 → 0.769 |
| IS1008a | 0/1/2 → 0/1/2 | 0.000 → 0.000 |
| ES2011a | NA，占位 gold，Decision 不计分 | 不计分 |

TS3006a 找回营收、成本两个独立选择。TS3006b 找回 LCD／语音识别，但失去原来匹配的顶部屏幕／麦克风布局项，
所以它的总 F1 持平。最后仍有 5 条未匹配：IS1008a 两条、TS3006b 的电视范围、布局和 LED。
这也说明修复没有解决所有初始抽取和合并选择问题，当前结果不能外推为整个开发集都会提升。

## 为什么采用这个组合

保留了两轮未采用实验，避免把不利结果隐藏：

| 实验 | Decision F1 | Action F1 | Issue F1 | 结论 |
| --- | --- | --- | --- | --- |
| 只在相同旧模型输出上改投票 | 0.593 | 0.706 | 0.500 | 会多出重复／无实质内容条目，不单独采用。 |
| 全类型一起更换合并提示词和投票 | 0.667 | 0.647 | 0.400 | Decision 改善，但影响其他类型，不整体采用。 |
| 单次带原文证据的独立复核 | 0.629 | 0.706 | 0.500 | 召回上升，precision 降至 0.524，且出现 Action 混入 Decision，不采用。 |
| 最终：保留旧 Action/Issue，Decision 独立三采样 | **0.667** | **0.706** | **0.500** | 本次采用。 |

新增阶段通常每场增加 3 次合并请求，缓存命中时不调用模型。本轮四场实际用了 14 次成功请求
（两次结构化成员列表不可用后重试），已知输入＋输出用量共 173,482 token，平均约 43,371／场。
这不是全流程耗时测试；并发、缓存与重试会影响实际耗时。初次沙箱网络失败的记录另行保留，不混入已知模型用量。
