## 代码问题和模型波动的证据

1. 同样的 11 份坏提交在 v9/v14 schema 中拒绝相同。v14 的 14 次无效动作含 11 次 schema 拒绝、3 次查询规则拒绝，不能把次数增加直接解释为字段要求变严。旧两版初始条目上下文相同，但系统提示不同，完整运行差异也不能全部归于随机性。
2. 控制器原来仅保护 accept 路径：条目因 deadline 缺失提出 clarification 时，尚未检查的必要历史可能被跳过。相同初检结果回放证明新控制器提供历史检索、继续搜索和停止的机会，不代选历史记录或生成关联。
3. 同版本的三次目标条目首次实际模型请求 SHA-256 一致，owner/status 判断、查询词、关系选择和终止仍不同。不同版本的工具/系统提示有变化，因此仅在版本内部用同请求证据确认输出波动。单条重复没有覆盖主输出。
4. 无进展检测原来受原因措辞影响：模型反复改写解释就被当成进展。现按未解决字段与代码产生的验证状态判断。相同真实停滞响应流，9 次→8 次并以 no_progress 退出，结果仍待确认。真实补读、来源修正仍可继续，已有真实 TV 范围更新回放保持通过。
5. 最新在线运行的目标条目已明确提交旧记录、updates、scope 变化及双方证据，却因额外重复的根级 evidence_da_ids 被拒绝两次。v19 仅删除与 quotes 完全相同的 ID 列表；单链接根级来源列表也只在与链接内选择完全一致时去重。引用文本、选择、关系和来源验证继续保留。

## 修改范围与边界

- 无歧义别名、完全相同的冗余选择、空/可选 null 文档选择可无损整理。原始参数及每次整理均入 trace。不同选择、未知 ID、非空不明归属文档、缺失正向/逐条关联证据继续拒绝。
- 不确定且未选关系时可补 links=[]；不会补造正向链接、来源或判断理由。格式错误反馈明确当前工具键名及层级。
- 历史阶段聚焦当前任务及已交付证据，已读旧记录 ID、双方源 ID 纳入工具契约。模型继续自主查找、补读、再次搜索或停止；continues/updates 与 changed_fields 的原有一致性约束在工具中明确表达。
- 仍只读取同系列更早会议。调用 80、token 1,000,000、请求超时 300 秒、整场超时 1200 秒、并发 4、重试 2、工具额度和终止上限均未提高。协议版本 14→19。
