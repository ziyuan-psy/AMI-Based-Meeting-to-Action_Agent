# 空缓存试跑后的针对性修复

开发基于 `agent-development@3b886f6`，本次修改未提交。没有修改 UI、标注文档或上一轮冻结产物。

1. 最终 Action 上限仍为 5。负责人覆盖不再排除 priority=1 的明确任务，并过滤空 ID。最多先核验 10 个 Action 候选，再用 P2 核验后的负责人/时间执行最终上限；证据失败与“通过核验但被数量上限省略”分别保存。后者的完整检查及待确认项在 verified_omitted checkpoint，不会伪装成证据失败。相同候选池的排序对比见每次实验的 captured_cap_comparison.json。
   Action 正文采用任务短语，负责人保留在独立字段；实际发言者的承诺须由原文支持。这样 P2 可以独立纠正归属，不会把抽取时猜错的人名永久嵌入任务正文。接收者、对象、条件和时间继续保留。
2. P2 的一次核心复查同时覆盖 assessment 和 Agent 的 terminal 工具出口。缺少时间、有限证据范围本身不等于核心任务矛盾；仍由模型复查和选择继续待确认。未读取、错误引用、文档来源不满足等错误无法用该复查绕过。
3. 修正工具仅在当前正文存在符合既有删除规则的尾部限定时开放。参数菜单限定为可删除的原文片段和已交付的当前会议证据 ID；不会替模型填补空理由、空引用或编造修改。成功删除仍须撤销原检查并重新检查全部字段，每条仍最多一次修改。
4. 本地检查通过、但历史尚未检查时，accept 建议会先获得自主检索机会。返回候选后直接让 Agent 选择读取、改变搜索或停止，避免重复提交缺少历史证据的完整 assessment。当前字段仍可读取当前对话；同系列、更早会议的代码边界保持。仅含会议 ID 的无效查询会收到修正反馈。
5. focused `assess_relation` 必填 `links`，每条明确选择旧记录、关系、变化字段、理由和双方已交付的源 ID；省略冗余 related_items 时只从这些显式选择生成字段。已读取来源但提交不完整时有一次有界修正机会，不能自动补造证据。针对核心复查，夹带的已知辅助字段只记录、不应用，避免无关格式错误删除可核验任务。只缺时间/状态时不再提供无关的参与者工具，会议/记录/同轮条目 ID 也不能当内容检索词。

6. 选择阶段明确 keep=false 时，可省略语义已确定的空 claims 数组；保留条目缺正文、缺候选编号仍拒绝。错误反馈现在指向具体 C-key，原始响应与补空数组记录都保存在 trace，既不生成新条目也不替模型填写证据。
7. 首场会议或禁用历史读取时，不适用历史检查可以由代码补齐。省略或空的 next_action 提示由控制器根据检查结果保守选择补查/澄清。非正向检查没有选择证据时使用空列表，没有原因则明确记录“模型未解释”；范围不明的冲突继续阻断正文。正向事实的原因、来源与支持证据不能用这些缺省值补造。

最终缓存策略版本：ITEM_POLICY_VERSION 5 → 8；P2_PROTOCOL_VERSION 6 → 9。调用/token/时间/重试/并发/工具次数限制均未提高。中间实验 repair-v1 使用 ITEM_POLICY_VERSION=6，repair-v2 使用 P2_PROTOCOL_VERSION=7，repair-v3 使用 ITEM_POLICY_VERSION=7，repair-v4 使用 P2_PROTOCOL_VERSION=8。

验证分为边界测试、相同旧候选池的确定性重放、相同三场 TXT 的新空缓存完整真实运行，以及沿用上轮相同输入的独立有限修正诊断。完整运行保留自身抽取和合并结果，不复制旧模型响应、候选或旧历史记录。
